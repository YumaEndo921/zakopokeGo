# Go Testing Standard Skill

このスキルは、`zakopokeGo` プロジェクトにおけるテストの書き方を定義します。現在はテストが実装されていませんが、今後の開発で品質を担保するため、以下の基準に従ってテストを作成してください。

## テストの基本構成

- **ファイル命名**: 対象ファイルと同じディレクトリに `xxx_test.go` という名前で作成します。
- **パッケージ名**: 対象ファイルと同じパッケージ名を使用します。
- **標準ライブラリ**: `testing` パッケージを基本とし、アサーションには必要に応じて `testify/assert` などの利用を検討します。

## テストの対象と手法

### 1. Domain Layer (Model)
- コンストラクタやバリデーションロジックに対する単体テスト。
- 外部依存がないため、最も手厚く行うべき箇所です。

### 2. Application Layer (UseCase)
- リポジトリインターフェースをモック化してテストします。
- ビジネスロジックの分岐（例：ポケモンの捕獲成功/失敗）を網羅します。

### 3. Infrastructure Layer
- DBやAPI通信のテスト。
- 実際のDB（テスト用）やHTTPスタブを使用して、通信の整合性を確認します。

## テスト実行コマンド

```bash
# プロジェクト全体のテストを実行
go test ./...

# 特定のパッケージのテストを実行
go test ./internal/application/usecase/...

# 詳細出力を表示
go test -v ./...
```

## モックの作成指針

- リポジトリインターフェース（`internal/domain/repository`）に対して手動または `mockgen` を用いてモックを作成し、UseCaseのテストに注入します。

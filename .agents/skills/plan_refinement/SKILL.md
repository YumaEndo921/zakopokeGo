# Plan Refinement Skill

このスキルは、AIが自身で立てた計画に対して「本当にこれでベストか？」と問い直し、ユーザーにより付加価値の高い提案を行うためのものです。

## 評価とブラッシュアップの観点

計画を作成した際、以下の3つの観点で自己レビューを行います。

### 1. 実現可能性とシンプルさ (Simplicity)
- **依存関係**: 無駄にライブラリを増やしていないか？
- **DB設計**: 既存テーブルを汚さず、将来の拡張に耐えられる構造か？
- **DDD**: レイヤードアーキテクチャの責務（`domain`, `usecase`, `handler`）を遵守しているか？

### 2. UI/UXの美学 (Aesthetic)
- **WOW要素**: ユーザーが初めてその機能を使った時に「可愛い！」「すごい！」と思える仕掛け（マイクロアニメーション、グラデーション、気の利いた絵文字）があるか？
- **一貫性**: 既存の「ギャル風」デザインと調和しているか？

### 3. 未知のリスクと回避策 (Risk Management)
- **パフォーマンス**: PokeAPIへのリクエストが多すぎて遅くならないか？
- **バリデーション**: 不正な入力でサーバーが落ちないか？

## 提案のフォーマット

ブラッシュアップした結果、元の案より優れた解決策や、対立するアプローチがある場合は、以下のように「提案」として提示してください。

```markdown
### 💡 計画のブラッシュアップ提案

作成した計画を見直し、以下の追加提案をさせていただきます。

#### オプション案: [案のタイトル]
- **メリット**: 〜〜
- **デメリット**: 〜〜
- **採用すべきシーン**: 〜〜

#### ＋アルファのWOW提案
「[機能名]」の画面ですが、単に表示するだけでなく、[具体的な演出案（例：キラキラ光るパーティクルを出す、など）]を追加することで、よりプレミアムな体験になりますがいかがでしょうか？
```

## 注意事項
- ユーザーに「選ばせる」ことが目的です。独断で複雑な実装に変更せず、必ずメリット・デメリットを示して確認を仰いでください。

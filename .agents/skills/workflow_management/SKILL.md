# Workflow Management Skill

このスキルは、AIがプロジェクト全体を俯瞰し、着実にステップを踏んで開発を進めるための「プロジェクトマネジメント」のガイドです。

## 開発の標準フェーズ

AIは開発を以下のフェーズに分割し、それぞれで明確なマイルストーンを設けます。

1. **Phase 1: 要件定義 (Requirements Definition)**
   - `requirements_definition` スキルを使用します。
   - 完了条件: `prd.md` が作成され、ユーザーが承認している。
2. **Phase 2: システム設計 (System Design)**
   - `system_design` スキルを使用します。
   - 完了条件: `implementation_plan.md` にER図やエンドポイントが記載され、ユーザーが承認している。
3. **Phase 3: 実装 (Implementation)**
   - `go_ddd`, `ui_standards` スキルを使用します。
   - `task.md` （TODOリスト）を作成し、進捗を `[ ]`, `[/]`, `[x]` で記録・更新しながら進めます。
   - 完了条件: 全ての機能の実装が終わり、コンパイルエラーがない。
4. **Phase 4: テスト・検証 (Testing & Verification)**
   - `go_testing` スキルを使用します。
   - 実装した機能が要件（PRDのAcceptance Criteria）を満たしているかテストし、ブラウザ上で正常に動作することを確認します。
5. **Phase 5: レビュー・完了 (Review & Documentation)**
   - `review_guidelines` スキルを使用します。
   - `walkthrough.md` を作成し、何を行い、何を検証したかユーザーに報告します。

## 進行管理におけるAIの振る舞いルール

- **独走の禁止**: 各フェーズの「完了条件」を満たす前に次のフェーズを開始しないでください。特に Phase 1 と Phase 2 の承認は必須のチェックポイントです。
- **現在地の提示**: ユーザーへの返答時、「現在は要件定義のフェーズです」や「実装フェーズを完了し、テストに進みます」など、今どの作業をしているか明言してください。
- **タスクの細分化**: `task.md` では粒度を細かくし、ユーザーが「AIが今どのファイルの何のロジックを書いているか」を把握できるように努めてください。
